# 房地产项目资金隔离

建立项目公司独立账、地块楼栋、收支账户、监管额度、施工节点、多方审批与销售
交付证据之间的后台关系，支持"付款必须对应已核验工程或法定义务"，并对总部
调拨、关联交易、账户外回款触发冻结复核。所有数据均为虚构样例，不含真实个人
信息、账号、密钥或连接凭据。

## 数据关系（fixtures/context.json，v2）

```
制度版本 regimes ──锁定── 合同 contracts ──收款──> 账户 accounts
政策变化 policy_changes（不追溯）        │          （预售监管户 / 现房结算户）
                                         ├── 单元 units ── 楼栋 buildings ── 地块 parcels ── 项目 projects ── 项目公司 actors（独立账 ledger_id）
                                         └── 交付证据 delivery_evidence（竣工备案 / 单体验收 / 交钥匙 + 可见房源公示 listings）

施工节点 construction_nodes ── 监理核验 node_verifications ──> 审批 approvals（项目公司/监理/住建/银行，接管后加接管主体）
法定义务 statutory_obligations ──────────────────────────────┘
审批 ──> 台账分录 ledger_entries（收正支负、幂等键、原收款引用、冻结复核引用）
银行回调 bank_callbacks（同幂等键重复到达只入账一次）
拦截 blocked_payments / 冻结复核 freeze_reviews / 风险接管 risk_takeover
多年审计 audit：封存期分录清单与代数和固化
```

## 核心不变量（src/domain.py: validate）

1. **项目公司独立账**：一个项目对应一家项目公司，项目账户开户主体只能是该公司，总部账户不挂项目。
2. **付款必须有依据**：`out` 分录只能是已核验工程节点（付款日不早于核验日、楼栋一致）、法定义务、原路退款或项目内划转；审批金额与拨付逐笔一致。
3. **监管额度**：逐楼栋节点拨付累计不得超过该楼栋 `supervised_quota_cny`。
4. **多方审批**：通过的拨付至少两方独立决定，任何一方决定时间不得晚于终审时间。
5. **冻结三触发**：总部调拨（无工程/法定义务依据，必须拒绝并留存在项目）、关联交易（增强复核通过后才放行）、账户外回款（责令原路缴回监管户）。
6. **规则不追溯**：每份合同锁定签署时生效的制度版本；政策变化 `retroactive` 恒为 false。2023 年签的预售合同仍按 REG-2020 执行，2024 年后的关联交易冻结规则不回写旧账。
7. **现房门槛**：现房合同必须绑定竣工验收备案 + 可见现房公示，签约日不早于备案日；未竣工楼栋（样例 5 号楼）被包装成现房时由住建直接拦截。
8. **资金归位**：预售款（含按揭放款）全额入预售监管户；现房款交付时结清入现房结算户，竣工后项目内划转以一进一出双生分录留痕。
9. **退款原路**：退款引用原收款分录，退回原付款来源（卡/贷款渠道），金额不超过原收款。
10. **风险接管**：接管宣布日后的拨付，审批链必须包含接管主体。
11. **回调幂等**：同一 `idempotency_key` 的重复银行回调只对应一笔拨付。
12. **多年审计一致**：封存期分录不重复，余额按"收正支负"代数和固化；任何被破坏的不变量都会在加载时报错。

## 三类使用视角

- **监管人员** — `trace_fund(raw, entry_id)`：沿任一台账分录串起 项目 → 地块 →
  楼栋 → 节点 → 核验报告 → 多方审批 → 冻结复核 → 最终用途。主办银行发现总部
  调账时，可用它立即回答"这笔钱对应哪座楼、哪项工程、哪份审批"。
- **主办银行** — `financing_view(raw)`：逐楼栋给出预售回款、监管额度、已核验
  节点拨付与额度余位，并给出融资原则（期房按额度余位、在建不可售楼栋只能按
  工程节点开发贷、现房不占用监管额度）。
- **购房人** — `buyer_delivery_view(raw, buyer_id, unit_id)`：只能查询本人所购
  房屋的竣工备案、单体验收、交钥匙证据与可见房源状态；查询他人房屋直接抛
  `PermissionError`，不泄露房源数据。

## 本地校验

```bash
python -m unittest discover -s tests   # 43 个用例：每条不变量 + 破坏后必须报错
```

读取器 `src/context.py:load_context` 同时兼容 v1 字符串清单与 v2 关联资料；
v2 资料加载时自动执行全部不变量校验。契约见
`contracts/context.schema.json`（可用 `jsonschema` 对样例做结构校验）。

## 样例覆盖的典型场景

- 1 号楼主体封顶节点经四方审批拨付，银行次日重复回调，仅入账一次；
- 总部 900 万调拨无任何工程依据，主办银行拦截 + 冻结复核，资金留存项目；
- 2 号楼向总部关联总包付款，触发关联交易增强复核（比价、重新现场核验）后放行；
- 购房款刷入总部关联 POS（账户外回款），责令缴回监管户后解除冻结；
- 购房人退房，款项按原付款卡退回；项目被宣告高风险后由城投接管，后续拨付加签；
- 5 号楼未竣工验收即被包装成现房签约，住建在后台直接拦截。
