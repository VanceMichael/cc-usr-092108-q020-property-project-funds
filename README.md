# 房地产项目资金隔离

整理房地产项目公司、银行账户、施工节点与销售交付证据，并建立它们之间的后台关系。

## 领域资料

`contracts/context.schema.json` 定义共享资料格式，`fixtures/context.json` 提供可公开使用的虚构样例。领域资料按版本保存参与者、事实与约束，代码中的读取器负责检查必要字段。

当前资料反映以下业务事实：

- 一个项目对应一家独立项目公司
- 开发建设销售资金由主办银行归集
- 新项目优先采用现房销售并强化预售资金监管
- 付款必须对应已核验工程节点或法定义务
- 总部调拨、关联交易、账户外回款触发冻结复核
- 合同继续遵循签署时的资金规则，制度变化不追溯
- 现房销售绑定竣工验收备案与可见房源状态

## 后台关系模型

`src/ledger.py` 把上述事实落成一份可校验的台账（结构契约见
`contracts/ledger.schema.json`，虚构样例见 `fixtures/ledger.json`）：

- **独立账**：项目有且仅有一个监管账户和一个一般账户，均开立在项目公司名下；总部账户是外部账户，项目付款不得从外部账户发起。
- **层级**：项目 → 地块 → 楼栋 → 房源；工程节点挂在楼栋上，带预算额度与监理核验记录。
- **付款依据**：工程进度款必须对应已核验节点且不超节点额度；税费、农民工工资等对应法定义务且按期；退款必须对应已解除合同且不超过购房人实缴。
- **冻结复核**：总部调拨、关联交易、账户外回款自动触发冻结复核；复核拒绝或退回的付款不得执行，账户外款项必须追回缴入监管专户。
- **制度快照**：合同记录签署时生效的制度版本（监管比例、是否允许预售），制度变化不追溯改写旧合同；现房合同必须绑定已竣工验收楼栋与可见在售房源。
- **多方审批**：已执行付款必须有开发企业、监理、银行三方审批；风险接管期间按接管级别追加专班审批或全面冻结。
- **回调幂等**：银行重复回调只记录为 `ignored_duplicate`，不重复入账。
- **审计链**：审计事件按年份顺序以 SHA-256 哈希链串联，任何篡改都会断链。

## 三类查询视图

- `buyer_view(ledger, contract_id, buyer)`：购房人只能查询自身房屋的交付证据（竣工验收、交付记录），看不到资金明细与他人信息。
- `bank_view(ledger)`：主办银行判断合理融资所需的项目汇总——监管户余额、已核验未付额度、未核验预算、未结冻结与接管情况。
- `trace(ledger, kind, id)`：监管人员沿任一资金流（付款 / 回款 / 房源）找到项目、楼栋、节点、审批与最终用途。

## 本地校验

运行项目自带测试可确认样例资料能够读取，且领域标识、版本和事实记录完整。样例不含真实个人信息、账号、密钥或连接凭据。

```bash
python -m unittest discover -s tests
```

修改样例后重新生成（含审计哈希链）：

```bash
python scripts/build_fixture.py
```
